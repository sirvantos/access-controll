# Tasks: User Authentication and Roles

**Input**: Design documents from `specs/001-user-authentication-and-roles/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [constraints.md](./constraints.md), [contracts/http-api.md](./contracts/http-api.md), [contracts/console.md](./contracts/console.md), [contracts/spa-routes.md](./contracts/spa-routes.md), [quickstart.md](./quickstart.md)

**Tests**: Required. Constitution §III (test-first) and quickstart §Scenario map ask for a Pest test for every acceptance scenario and a Vitest spec for every page. The factory runs `make verify` after each task, so every task writes its tests first and then the code that makes them pass. A task never leaves a failing test behind.

**Organization**: Tasks are grouped by user story. Phases follow the spec's priorities: P1 (US1, US2, US3), then P2 (US4, US5, US7), then P3 (US6).

## Format: `[ID] [P?] [Story] Description (depends on …)`

- **[P]**: Can run in parallel with the other [P] tasks of the same phase (different files, no dependency between them).
- **[Story]**: The user story the task serves (US1…US7).
- `(depends on …)` at the end of a line lists the tasks that must be done first. It never points at a later phase.

## Rules for every task

- Limits come from [constraints.md](./constraints.md). Each limit becomes a typed class constant named after the business field. Do not repeat bare numbers.
- Every PHP file starts with `declare(strict_types=1);`. Every model defines `casts()` for every column. Guards use `throw_if()` or `throw_unless()`. Closures are arrow functions.
- Business code lives in `app/Modules/{Identity,Companies}`. Other modules and `app/Http` import only `App\Modules\{Other}\PublicApi\*` (plan §Module boundary exceptions: none).
- Every domain exception lives in `app/Exceptions`, implements `Illuminate\Contracts\Debug\ShouldntReport`, renders the body from data-model §Domain exceptions, and has a `Log::fake()` silence proof in its feature test: assert no `error`-level (or higher) log entries from the exception handler. Sign-in failures are different: `SignInFailedException` and `SignInBlockedException` still use `ShouldntReport`, but their tests must also assert a structured authentication-failure log entry is written (plan §VI Observability) with only non-PII fields such as `event` and `reason`—never password, email, or token.
- Module input DTOs in `app/Modules/{Identity,Companies}/Data` extend `Spatie\LaravelData\Data`. Form Request `toDto()` builds them with Laravel typed request helpers (plan §Dependencies, constitution I.a).
- Every user-facing message has a key in `lang/en/*.php` and `lang/ru/*.php` (backend), or in `resources/js/locales/en.json` and `ru.json` (frontend). Tests compare against `__()` or `t()` keys, never pasted sentences.
- Every new `/api/v1` route is documented in `public/swagger.yaml` in the same task (checked by `tests/Feature/OpenApiDocumentTest.php` from T015).
- Emails are lowercased in `toDto()` and in the console command with Stringable `->lower()` (research R14). Do not trim; `TrimStrings` already does it.
- Tests use fixed sample values from `tests/Support/Identity` (T012), `Notification::fake()`, and `Carbon::setTestNow()`.
